On 5 November a macOS X64 run on main failed in a timer test. According to the description of PR #25, which fixes issue #22, the cause had three parts, and only one of them was the test being wrong. The other two are the kind of bug that stays hidden until a runner gets slow, so I think they are worth writing down.

The first was in @jess/net. When one poll wakes two tasks and the first closes the second task's connection, the release step cannot reach the second task, because it is no longer waiting. That task resumes still marked ready, reads a stream that is already closed, and raises. The TLS front's back task hit exactly this. The fix is small: release now turns a pending ready into closed, for any handle, whether it was waiting on a receive, a send, a TLS flush or net.wait. The regression test reproduces the issue's error message on every run before the fix. That matters. A test that fails only sometimes tells you little; one that fails every time before the fix and passes after it is evidence.

The second was ordering. When a scheduler step runs late and finds several timer deadlines already past, it woke them in whatever order the parked-task set yielded. In the new test the order before the fix was 1 4 3 2 5. The deadlines were right; the wake order was arbitrary. Now they wake in deadline order. The same late step had already flipped a quick/yielded check in the network suite on the macOS ARM64 runner, so this bug had a real footprint.

The third was the test. The timer test relied on a watchdog that checks the deadline only every 64 safepoints. The budgeted handler spun for 40 milliseconds. If the scheduler stalled for longer than that, the spin finished before the next check and the budget never tripped. The reported result, (1, 0), was the test running on a machine slower than its own assumptions. The budgeted firing now spins until it is stopped, with a 60-second limit as a backstop in case it never is.

The pattern across the network tests is the part I most want other contributors to take. Many of them measured speed: sleep for a while, expect a heartbeat inside a window, expect an answer within some gap. Those checks pass on a fast laptop and fail on a busy CI runner, and the failures look like flakiness rather than bugs. The PR changes what each answer depends on instead of how long it takes.

A slow answer in a liveness test now goes out only after heartbeats or other tasks have run. If the loop blocked, the test would deadlock and fail on any machine, so no gap needs to be measured. Chunked streams go out one step at a time under a fixture that lets the test release each piece. Concurrency is shown by three handlers that wait for each other, not by checking that they finished within a window. The handshake-timeout test now uses a separate server for the timeout, so the server taking real requests is not affected by it. Idle expiry gets its own test.

Some timing limits remain, but only where a failing run is the one that waits them out: receive deadlines, startup, hang fixtures. Each has room for a slow runner and still sits inside the backstop it is meant to tell apart from the others. For example, wait_until_idle stays under the server's read timeout, so it cannot outlast the thing it is checking.

There is a cost. The change is large: the PR reports about 824 lines added and 326 removed across fourteen files, including a new fixture module. Causal tests are harder to read at first, because the test has to say what it is waiting for rather than how long. The docs page that described the old timing checks was updated to describe what the suite checks now, which seems the right place for that change to live.

The result landed. v0.3.0 was released on 6 November. On the release commit, the test and lint jobs across Linux, Windows and the three macOS targets succeeded, and so did the release, crates.io and image jobs. That is what CI reported; I have not run the suite myself, and I would not tell you it is free of flakiness on every machine, only that these three causes are addressed and the reasons are written down.
